# Тесты Jiyda

Все тесты — здесь, в `tests/`. Два уровня:

| Уровень | Где | Что проверяет | Запуск |
|---|---|---|---|
| **Модульные** (Rust) | `tests/unit/<модуль>.rs` | чистую логику без окна: модель страниц, хранилище, сочетания клавиш, настройки, обновления, перенос данных… | `cargo test` |
| **E2E** (настоящий браузер) | `tests/e2e/` | Jiyda целиком: окно, интерфейс, страницы в WebView2, ядро | `cargo build; pwsh tests/e2e/run.ps1` |

CI (`.github/workflows/windows.yml`) запускает оба уровня на каждый push; E2E — дважды, со своей рамкой окна и с обычной рамкой Windows. Упавший E2E прикладывает к запуску снимок экрана и стеки потоков.

## Модульные тесты

Каждый файл `tests/unit/<модуль>.rs` подключён к своему модулю в `src/` строками в конце файла:

```rust
#[cfg(test)]
#[path = "../tests/unit/page_list.rs"]
mod tests;
```

Поэтому тесты лежат отдельно от кода, но остаются дочерним модулем и видят приватные функции (`use super::*;`). Имя файла — путь модуля через `_`: `src/app/ui_assets.rs` → `tests/unit/app_ui_assets.rs`, `src/app/mod.rs` → `tests/unit/app.rs`.

Новый модуль с тестами: создать `tests/unit/<имя>.rs` (начать с `use super::*;`) и добавить три строки выше в конец модуля. Cargo не считает файлы в подпапках `tests/` отдельными интеграционными тестами, так что двойного запуска нет.

```
cargo test                    # все
cargo test page_list::        # один модуль
cargo test mru_walk           # по части имени
```

## E2E

```
cargo build                                   # отладочная сборка: канал автоматизации есть только в ней
pwsh tests/e2e/run.ps1                        # все сценарии
pwsh tests/e2e/run.ps1 -Filter 'spaces|split' # по имени (регулярное выражение)
pwsh tests/e2e/run.ps1 -NativeFrame           # с обычной рамкой Windows
pwsh tests/e2e/run.ps1 -Report out/junit.xml  # отчёт JUnit
```

Как устроено:

- `run.ps1` — запускает тестовый сайт (`server.ps1`, файлы из `site/`, `http://localhost:8765/`) и `jiyda.exe` с чистой временной папкой данных (`JIYDA_DATA_DIR`) и каналом автоматизации (`JIYDA_AUTOMATION=1`). Обновления не проверяются, загрузки идут во временную папку. Через `automation.txt` загружает `harness.js` и все `specs/*.spec.js`, запускает их и собирает итог из журнала.
- `harness.js` — мини-фреймворк внутри интерфейса: `E2E.test(name, fn)`, перед каждым тестом `t.reset()` (ни страниц, ни слоёв, одно пространство).
- `specs/NN-<область>.spec.js` — сценарии по областям; номер задаёт порядок. Каждый файл выполняется в своей области видимости (одинаковые имена констант в разных файлах не конфликтуют); файл с синтаксической ошибкой проваливает прогон.
- `restart/<имя>.before.spec.js` + `<имя>.after.spec.js` — перезапуск: «before» собирает состояние, Jiyda закрывается и открывается с тем же профилем, «after» проверяет восстановление (без `t.reset()`). Строка `// restart: kill` в «before» — процесс убивается, как при сбое, без сохранения при выходе (`crash.*`).
- `diagnostics.ps1` — при сбое: окна процесса, снимок экрана, стеки потоков (cdb).

Тест провален, если: сценарий бросил ошибку; в журнал попала ошибка JS интерфейса (`интерфейс: …`) или паника; Jiyda завис или не закрылся.

### API теста (`t`)

| | |
|---|---|
| `await t.open('a.html', mode)` | открыть адрес как адресная строка (`new` / `current` / `split` / `background`), дождаться загрузки → страница |
| `t.state()`, `t.pages()`, `t.nowPages()`, `t.active()`, `t.page(id)`, `t.byUrl('a.html')` | состояние, которое ядро прислало интерфейсу |
| `t.post({type: …})`, `t.cmd('orbit')` | сообщение ядру (см. `src/ipc.rs`), команда (см. `src/command.rs`) |
| `await t.waitFor(() => cond, 'что ждём', ms)` | ждать условия (может быть async); по таймауту — понятная ошибка |
| `await t.evalPage('js', id)` | выполнить код в странице (0 — активная) и вернуть результат |
| `t.$`, `t.$$`, `t.type(el, text)`, `t.key(el, 'Enter')` | интерфейс: найти элемент, «напечатать», нажать клавишу |
| `t.ok(cond, msg)`, `t.eq(actual, expected, msg)` | проверки |
| `t.layerOpen('palette')`, `t.url('a.html')`, `t.sleep(ms)` | |

Пример:

```js
E2E.test('later: moves page to Later and activates another', async (t) => {
  const a = await t.open('a.html');
  const b = await t.open('b.html');
  t.post({ type: 'later', id: b.id });
  await t.waitFor(() => t.page(b.id).state === 'later', 'B в Later');
  t.eq(t.state().active, a.id, 'активна A');
});
```

Правила:

- Ждать состояния через `t.waitFor`, а не `t.sleep` — иначе тест будет то медленным, то нестабильным. `sleep` — только чтобы убедиться, что чего-то **не** произошло.
- Имя теста: `<область>: <что проверяем>`, по-английски; сообщения проверок — по-русски, как журнал.
- Нужна страница с особым содержимым — добавить её в `site/`.
- Отладить один случай: положить сценарий в отдельную папку и `run.ps1 -SpecDir <папка>`.
- Только в отладочной сборке: команда автоматизации `jsfile` и сообщение `e2e_eval` (выполнить код в странице) — в релизе их нет.
