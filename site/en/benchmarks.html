Benchmarks

Measured 19 October 2026

In short: with one page open, Jiyda uses less memory than Edge and Chrome and almost no processor time while idle. With 10 or more pages it needs about 1.7–2 times more memory, and opening 50 pages at once takes several seconds. We publish both, and we are working on the second.

How we measured

  • Every run starts the browser with a new empty profile and opens 1, 10 or 50 copies of the same article page (text, tables, images, no animation) from a local server — no internet involved.
  • Each page comes from its own address (127.0.0.1, 127.0.0.2…), so 50 pages are 50 different sites, like ordinary tabs.
  • “Start to first page” is the time from launching the browser to the page’s load event; “all pages loaded” — to the last page’s load event.
  • Memory is the sum over all the browser’s processes (main, pages, GPU and others) 10 seconds after loading. Private memory is what the browser uses exclusively; working set also counts shared memory and is shown for completeness.
  • Idle CPU is processor time used by all those processes over 20 seconds of doing nothing, as a percentage of one core.
  • Each number is the median of three runs after one warm-up run.

What these numbers do not say

  • They come from one machine and one version of each browser. Results on other hardware will differ.
  • Battery life and crash rates are not measured here — they need long observation on laptops.
  • Opening 50 pages at once is unusual. When Jiyda restores a session, pages stay asleep until you open them.

What benchmarks already fixed

The first run showed that an animated highlight in Jiyda’s top bar kept redrawing it all the time, using about 13% of a processor core while idle. It is gone: now it is about 0.1%.

Reproduce

The script, the page and the raw results of every run are in the repository: bench/. Run bench/run.ps1 on your own machine.
