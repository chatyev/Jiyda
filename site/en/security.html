Security

Updated 18 October 2026

How Jiyda is built

  • The engine is Microsoft Edge WebView2, based on Chromium. Microsoft keeps it up to date through Windows (the “Evergreen” runtime), so security fixes in the page engine arrive without waiting for a Jiyda release.
  • Jiyda’s own code is written in Rust, a language that rules out whole classes of memory errors. Its interface runs in a separate, isolated origin from the websites you visit.
  • Spaces are isolated. Each Space has its own browser profile: cookies, logins, cache and storage are not shared between Spaces.

Protection while you browse

  • Sites with invalid certificates are blocked, and pages without HTTPS are marked in the address bar.
  • Known trackers and ad networks are blocked by default. The block lists are built into Jiyda; nothing is downloaded or sent to check them.
  • Sites must ask before using the camera, microphone, location, notifications and other sensitive features. “Allow once” is never remembered; remembered decisions can be reviewed and reset in Settings.
  • A page cannot open an unlimited number of new pages: Jiyda stops pages that try.

Updates

  • New versions are published on GitHub Releases and downloaded over HTTPS only from that address.
  • Each installer is published with its SHA-256 checksum. Before running an update, Jiyda checks the downloaded file against it and refuses to run a file that was damaged or altered.
  • Updates are installed only after you confirm. Automatic checks can be turned off in Settings.
  • Jiyda is not yet signed with a code-signing certificate, so Windows SmartScreen may warn about the installer. Signing is planned before the public release.

How the code is checked

  • Every change is built and tested automatically: formatting and lint checks with warnings treated as errors, more than 250 unit tests, and over 100 end-to-end tests that drive the real browser.
  • Every build checks all Rust dependencies against the RustSec vulnerability database and verifies their licenses and sources (cargo-deny).

Data

Jiyda does not collect your browsing history, addresses, searches or page contents, and has no analytics or crash reporting. Details are in the Privacy Policy.

Reporting a vulnerability

If you find a security problem in Jiyda, please write to d.chatyev@gmail.com with “Security” in the subject. Please include:

  • the Jiyda version (Settings → Advanced) and your Windows version;
  • steps to reproduce, and what an attacker could achieve;
  • a proof of concept, if you have one.

We will reply within 7 days, keep you informed while we fix it, and credit you in the release notes if you wish. Please give us reasonable time to release a fix before you share details publicly, and do not access other people’s data while testing. We do not take legal action against good-faith research that follows these rules. We do not offer a paid bug bounty yet.

Problems in the page engine itself (WebView2 / Chromium) should also be reported to Microsoft.
