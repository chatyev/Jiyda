# Лицензия Jiyda: варианты

Не юридическое заключение — сравнение, чтобы выбрать, а потом проверить с юристом.

## Что сейчас

- Репозиторий **chatyev/jiyda публичный, файла LICENSE нет**. По умолчанию это значит
  «все права защищены»: код можно читать, но нельзя законно копировать, менять и
  распространять. Это не open source.
- Сайт в разделе «Написан на Rust» пишет «Исходный код открыт на GitHub» — верно в смысле
  «можно прочитать», но многие поймут как open source.
- План (раздел 3) советует **закрытое ядро** на этом этапе: главное преимущество — UI/UX
  и продуктовая модель, сообщества пока нет, ранний open source облегчает клонирование.

## Почему нельзя просто сделать репозиторий приватным

- Установщики лежат в **Releases этого репозитория**: у приватного репозитория их не
  скачать без входа — сломаются кнопка «Скачать» на сайте и **автообновление у всех
  установленных Jiyda** (src/update.rs ходит на github.com/chatyev/jiyda/releases).
- **GitHub Pages** для приватного репозитория — только на платном тарифе.
- Выход: код — в приватный репозиторий, выпуски и сайт — в отдельный публичный
  (например, chatyev/jiyda-releases), и CI публикует туда. Так уже сделан мост для Seyro.
  Но адрес выпусков зашит в установленных Jiyda — переход надо делать выпуском, который
  сначала научится брать обновления из нового места.

## Варианты

| Вариант | Что можно другим | Плюсы | Минусы |
|---|---|---|---|
| **A. Source-available, все права защищены** (файл LICENSE: «Copyright … All rights reserved. Исходный код опубликован для ознакомления и проверки безопасности») | только читать | ничего не ломается; соответствует плану (закрытая модель); проверяемая приватность — сильный довод для браузера | не open source: сообщество не может законно присылать и переиспользовать код |
| **B. FSL-1.1 (Functional Source License) → Apache-2.0 через 2 года** | читать, менять, использовать — кроме конкурирующего продукта; через 2 года каждая версия становится Apache-2.0 | защищает от клона-конкурента сейчас, честно «почти открыт»; используют Sentry и др. | непривычна, не OSI-лицензия; нужна аккуратность в формулировках |
| **C. MPL-2.0** (как у Firefox) | всё, но изменённые файлы — под той же лицензией | настоящий open source; правки Jiyda остаются открытыми | клон-форк с другим брендом законен (бренд защищает только товарный знак) |
| **D. GPL-3.0** | всё, но форк целиком — под GPL | сильнее всего мешает закрытым форкам; вы как автор можете продавать другую лицензию | отпугивает часть контрибьюторов; совместимость с некоторыми зависимостями проверять |
| **E. MIT / Apache-2.0** | всё, включая закрытые форки | максимальное доверие и простота | конкурент может взять код целиком в закрытый продукт |

Во всех вариантах **имя и логотип Jiyda** защищает товарный знак, а не лицензия кода —
поэтому проверка и регистрация знака (docs/brand) нужны в любом случае.

## Рекомендация

Сейчас — **A** (или **B**, если хочется, чтобы код можно было законно запускать и
менять для себя). Это совпадает с планом, ничего не ломает в выпусках и обновлениях и
делает текст сайта точным. Открывать отдельные компоненты (блокировщик трекеров,
шифрование синхронизации) — позже, как предлагает план.

После выбора:

1. Добавить `LICENSE` в корень репозитория.
2. На сайте в карточке «Открытый код» написать точно: для A — «Код опубликован для
   проверки», для B — «Код открыт по лицензии FSL», для C–E — «Open source, <лицензия>».
3. В манифесте WinGet (packaging/winget) поменять `License: Freeware` на выбранную.
4. Добавить в README раздел «Лицензия».
